§05

Mekanik Montaj

Gövde, tek seferde değil alttan yukarıya doğru katman katman monte edilir; her katman bir öncekinin üzerine sarı spacer çubuklar ve somunlarla oturur.

  1. Katman 1 — Motorlar & sürücüler

    İki Pololu motor ve iki BTS7960 sürücü en alt katmana sabitlenir. Motorların hangisinin SOL/SAĞ olacağı burada fiziksel olarak belirlenir — pin haritasıyla (§04) tutarlı olmalı.

  2. Katman 2 — ESP32-S3 & XL4015E1

    Mikrodenetleyici ve güç regülatörü ikinci katmana yerleştirilir; motor/encoder kabloları bu katmana çıkar.

  3. Katman 3 — Raspberry Pi 4

    Üçüncü katman RPi4'ü taşır; XL4015E1'in 5V çıkışı buraya USB-C ile bağlanır.

  4. Katman 4 — LIDAR

    En üst katman LIDAR'ı taşır — 360° görüş açısı için diğer katmanların üzerinde, engelsiz bir konumda olmalı.

  5. Tekerlek montajı

    Motor D-şaftına önce şaft adaptörü, sonra tekerlek geçirilir. Bu arayüz, projenin en kritik tolerans noktasıdır — aşağıdaki tasarım notuna dikkat edin.

Tasarım notu — şaft adaptörü toleransı Motor şaftı 4mm D-profil, plastik (3D baskı) bir adaptöre zorlanarak geçirilirse, plastik mikro düzeyde deforme olup merkezden kayar — bu, tekerlek dönerken gözle görülür bir sallanmaya ("8 çizme") yol açar. Doğru yaklaşım: deliği şafttan hafif büyük (4.0–4.2mm) tasarlayıp hiç zorlamadan geçirmek, sabitlemeyi bir set vidası + M3 somun cebi (şaftın düz D-yüzeyine bastıran) ile yapmak, delik çevresinde en az 3–4mm dolu et kalınlığı bırakmak, ve baskı sonrası deliği gerçek bir 4mm matkap ucuyla raybalamak.
§06

ESP32-S3 Firmware Kurulumu

Yükleme yöntemi PlatformIO'dur (Arduino IDE değil) — micro-ROS yalnızca PlatformIO ile derlenebilir. ESP32-S3'ün dahili native USB'si sayesinde ayrı bir USB-TTL adaptörüne gerek yoktur.

  1. PlatformIO CLI kurulumu

    pip install platformio

  2. linorobot2_hardware deposunu klonla

    git clone -b humble https://github.com/linorobot/linorobot2_hardware.git
cd linorobot2_hardware/firmware

  3. Doğru config'i doğrula

    config.h içinde USE_ESP32S3_CONFIG tanımlı olmalı; motor/pin/kalibrasyon değerleri config/custom/esp32s3_config.h içindedir (§04'teki pin haritasıyla aynı).

  4. İki zorunlu kod yaması (upstream'den fark)

    Bu robotta, resmi depodan sadece iki dosyada, iki satır değiştirildi — bunlar olmadan motorlar hiç dönmez / encoder hiç veri üretmez. Aşağıdaki iki değişikliği uygulayın.

  5. Derle ve yükle

    pio run -e esp32s3 -t upload --upload-port /dev/ttyACM0

    Native USB portunda otomatik reset devresi olmadığından, yükleme sırasında BOOT tuşuna basılı tutup RESET'e dokunmak gerekebilir.

  6. Doğru portu ayırt et

    Kartın iki USB-C portu vardır: idVendor=303a (native USB — Serial/micro-ROS için kullanılan budur) ve idVendor=1a86 (UART köprü — sadece flaşlama). Karıştırmayın.

Yama 1 — firmware/lib/encoder/encoder.h (satır 52)

Açık-kolektör (open-collector) encoder'lar için ESP32Encoder kütüphanesinin varsayılan pull-DOWN ayarı hiç veri üretmez; pull-UP'a zorlanmalı. attachHalfQuad() çağrısından hemen önce, Encoder yapıcısının (constructor) içine eklenir:

Encoder(int pin1, int pin2, int counts_per_rev, bool invert = false) {
    int temp_pin = pin1;
    if (pin1 < 0 || pin2 < 0) return; // unused encoder
    if(invert)
    {
        pin1 = pin2;
        pin2 = temp_pin;
    }
    counts_per_rev_ = counts_per_rev;
    ESP32Encoder::useInternalWeakPullResistors = puType::up;  // <-- EKLENEN SATIR
    encoder_.attachHalfQuad(pin1, pin2);
}

Yama 2 — firmware/src/firmware.ino (satır ~295)

ROS2 Humble'ın rclc kütüphanesinde rclc_timer_init_default2 (5 argümanlı) yoktur, sadece 4 argümanlı rclc_timer_init_default vardır. Upstream kod bazı dallarda 5 argümanlı ismi kullanıyor olabilir — Humble'da derleme hatası verir, aşağıdaki gibi olmalıdır:

// create timer for actuating the motors at 50 Hz (1000/20)
const unsigned int control_timeout = 20;
RCCHECK(rclc_timer_init_default(   // <-- "rclc_timer_init_default2" DEĞİL
    &control_timer,
    &support,
    RCL_MS_TO_NS(control_timeout),
    controlCallback
));
§07

Raspberry Pi 4 Kurulumu — Komut Günlüğü

Bu bölüm, RPi4 üzerinde fiilen çalıştırılan tüm komutları, sırasıyla, hiçbir adım atlanmadan belgeler. Amaç: aynı kartı sıfırdan, bu kılavuzu takip ederek, hiçbir komutu tahmin etmeden yeniden kurabilmek.

Faz 1 — İşletim sistemi

  1. Raspberry Pi Imager ile yazma

    Seçilen imaj: Ubuntu Server 22.04.5 LTS (64-bit) — Desktop değil (gereksiz RAM/CPU), 32-bit değil (ROS2 Humble'ın resmi packages.ros.org deposu sadece arm64 sağlıyor).

    Imager'ın gelişmiş ayarları (⚙️) ile SD karta yazmadan önce yapılandırılanlar: Hostname raspberrypi4, SSH etkin (şifre ile), kullanıcı pi4, WiFi SSID/şifre, saat dilimi Europe/Istanbul, klavye düzeni tr.

  2. İlk SSH bağlantısı

    ssh pi4@<rpi-ip>

    IP, DHCP ile atanır; her açılışta değişebilir (router'ın DHCP istemci listesinden ya da ping ile ARP taramasından bulunabilir — bkz. §10).

    uname -m   # aarch64 çıkmalı — 64-bit doğrulaması

  3. Sistem güncelleme

    sudo apt update && sudo apt upgrade -y

    Karşılaşılan sorun: Hash Sum mismatch hatası (birkaç farklı pakette, rastgele). Geçici çözüm: komutu tekrar çalıştırmak (genelde 2. denemede geçiyor). Kalıcı kök neden ve çözüm için bkz. §10 — bu, kurumsal ağın şeffaf HTTP proxy'sinden kaynaklanıyordu.

    Kernel güncellenirse (5.15.0-1061 → 5.15.0-1105-raspi gibi) yeniden başlatın: sudo reboot

  4. Locale (dil/karakter kodlaması)

    locale
sudo apt install locales -y
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8

    ROS2'nin DDS katmanı ve colcon/rosdep UTF-8'e güveniyor; minimal Ubuntu Server kurulumunda locale bazen C/POSIX kalıyor.

Faz 2 — ROS 2 Humble

  1. Resmi ROS2 apt deposu

    sudo apt install software-properties-common -y
sudo add-apt-repository universe
sudo apt update && sudo apt install curl -y
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update

  2. Paket kurulumu (ros-base, desktop değil)

    sudo apt install ros-humble-ros-base -y
sudo apt install python3-colcon-common-extensions python3-rosdep python3-argcomplete -y
sudo rosdep init

echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc

    Neden ros-base, desktop değil: RPi'ye ekran bağlanmıyor (başlangıçta) — RViz/Gazebo gibi GUI araçlarına ihtiyaç yok, gereksiz paket/RAM kullanımından kaçınılıyor. (Not: proje ilerledikçe RPi4'e fiziksel ekran da bağlandı ve GNOME masaüstü sonradan kuruldu — bkz. §10, bu normalde RPi3B+'ta önerilmeyen bir şeydi ama RPi4'ün 4GB RAM'i bunu kaldırabildi.)

Faz 3 — micro-ROS agent workspace

  1. Agent kaynak kodu ve derleme

    sudo apt install git -y

    Bu adım sadece micro_ros_setup betik paketini derler (birkaç saniye). Asıl agent henüz yok.

  2. Agent'ın kendisini oluştur ve derle

    RPi4'te (4GB RAM) ~4-5 dakika sürer. Düşük RAM'li kartlarda (RPi3B+ gibi, 1GB) swap dosyası gerekebilir — /etc/fstab'a eklenmezse her reboot'ta kaybolur.

  3. Test (ESP32 bağlıyken)

    ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyACM0 -b 921600

    Başka bir terminalde ros2 topic list ile /cmd_vel, /odom/unfiltered, /imu/data görülmeli.

Faz 4 — Tam linorobot2 kurulumu (Nav2/SLAM/URDF)

  1. Resmi kurulum betiği

    source /opt/ros/humble/setup.bash

    Betik ~/linorobot2_ws'u oluşturur: URDF (linorobot2_description), Nav2 config (linorobot2_navigation), SLAM Toolbox config, ikinci bir bağımsız micro-ROS agent kopyası. LINOROBOT2_BASE=2wd ortam değişkeni ~/.bashrc'ye eklenir.

  2. LDS-01 sürücüsünü elle ekle

    cd ~/linorobot2_ws/src

cd ~/linorobot2_ws

    Çalıştırma: ros2 launch hls_lfcd_lds_driver hlds_laser.launch.py (bkz. scripts/start_robot.sh). linorobot2_bringup.service'in ExecStart'ı (systemd/install_agent_service.sh) LINOROBOT2_LASER_SENSOR'ü unset eder, böylece bringup hiçbir LIDAR'ı otomatik başlatmaya çalışmaz — LIDAR her zaman start_robot.sh ile ayrıca başlatılır.

  3. Elle bringup (systemd kurulmadan önce, ilk test için)

    ros2 launch linorobot2_bringup bringup.launch.py micro_ros_baudrate:=921600

    micro_ros_baudrate mutlaka esp32s3_config.h'deki BAUDRATE (921600) ile eşleşmelidir — varsayılan (115200) farklıdır ve agent ESP32 ile hiç konuşamaz.

Çözüm: spin()'i döngünün dışına, öncesine taşımak — döngü sadece zamanlamayı kontrol etmeli, PWM komutunu tekrar tekrar göndermemelidir.

Düzeltilmiş sampleMotors() — calibration/src/firmware.ino

Bu robotta fiilen kullanılan, düzeltilmiş hâli (spin() döngünün dışında, bir kere):

void sampleMotors(bool show_summary)
{
    if(Kinematics::LINO_BASE == Kinematics::DIFFERENTIAL_DRIVE)
    {
        total_motors = 2;
    }

    float measured_voltage = constrain(MOTOR_POWER_MEASURED_VOLTAGE, 0, MOTOR_OPERATING_VOLTAGE);
    float scaled_max_rpm = ((measured_voltage / MOTOR_OPERATING_VOLTAGE) * MOTOR_MAX_RPM);
    float total_rev = scaled_max_rpm * (SAMPLE_TIME / 60.0);

    for(int i=0; i<total_motors; i++)
    {
        Serial.print("SPINNING ");
        Serial.print(labels[i]);

        unsigned long start_time = micros();
        unsigned long last_status = micros();

        encoders[i]->write(0);
        motors[i]->spin(PWM_MAX);          // <-- DÖNGÜ DIŞINDA, TEK SEFER
        while(true)
        {
            if(micros() - start_time >= SAMPLE_TIME * 1000000)
            {
                motors[i]->spin(0);
                Serial.println("");
                break;
            }

            if(micros() - last_status >= 1000000)
            {
                last_status = micros();
                Serial.print(".");
            }
        }

        counts_per_rev[i] = encoders[i]->read() / total_rev;
    }
    if(show_summary)
        printSummary();
}
Bu komutun sayılarına körü körüne güvenmeyin sample'ın ürettiği COUNTS_PER_REV, MOTOR_MAX_RPM'in gerçek devirle birebir uyuştuğu varsayımına dayanır — bu projede bu varsayım güvenilmez çıktı (bkz. aşağıdaki bölüm). Kullanım komutu: seri port 9600 baud'da sample yazıp Enter'a basmak, iki motor için ~10'ar saniye sürer.

COUNTS_PER_REV — mezura ile geriye hesaplama yöntemi

Kalibrasyon firmware'inin sample komutu MOTOR_MAX_RPM'in doğru olduğu varsayımına dayanır (gerçek devri değil, teorik devri kullanır) — bu projede bu varsayım güvenilmez çıktı, iki ayrı denemede birbirinden çok farklı/tutarsız sonuçlar verdi. Onun yerine odometri ile gerçek mezura ölçümünü karşılaştırıp geriye doğru ölçek hesaplandı:

  1. 1 metre ve 2 metre düz sürüş testi

    Robot sabit hızda (/odom/unfiltered Euclid mesafesi 1.000m / 2.000m'ye ulaşınca duracak şekilde) sürülür, gerçek kat edilen mesafe mezurayla ölçülür.

  2. Ölçek oranı

    oran = odometri_mesafesi / gerçek_mesafe — bu projede 1.001/0.92 ≈ 1.088 (odometri %8.8 fazla okuyordu).

  3. Her iki COUNTS_PER_REV'i aynı oranda büyüt

    Eski ortalama değer × 1.088 — bu genel ölçek hatasını düzeltir (ileri/geri mesafe artık mezura ile birebir tutuyor), ama sol-sağ dengesizliğini (yön sapmasını) düzeltmez.

  4. Yön sapmasını ayrı hesapla

    2m düz giderken ölçülen yanal sapmadan (bu projede 4.5cm sola) dönüş yarıçapı R = mesafe² / (2 × sapma) ve gereken teker hız farkı L/R (L = teker arası mesafe) hesaplanır; bu oran, ortalama ölçeği koruyarak iki COUNTS_PER_REV arasında yeniden dağıtılır.

Tuzak — sample komutunun oranına güvenmeyin İlk denemede sol-sağ dengesizliği sample komutunun ham oranıyla (2287/2233) düzeltilmeye çalışıldı — sonuç yanlış yönde ve aşırı büyük bir düzeltme oldu, sapmayı düzeltmek yerine kötüleştirdi. Gerçek mezura ölçümünden geriye hesaplanan oran (yukarıdaki yöntem) doğru sonucu verdi. sample'ın mutlak sayıları MOTOR_MAX_RPM varsayımına bağlı olduğu için güvenilmez; sadece gerçek dünya ölçümünü referans alın.

§10

Bilinen Sorunlar ve Dersler

Bu projenin geliştirilmesi sırasında karşılaşılan ve kök nedeni bulunan sorunlar — sıfırdan aynı yığını kuran biri için en değerli kısım muhtemelen burasıdır.

Elektriksel

Ortak GND unutulursa

Belirli yön komutları çalışırken diğerleri "tekler", akım 0A okunur. Her fiziksel yeniden kablolamadan sonra ortak GND'yi elle kontrol edin.

Firmware

Encoder pull-down varsayılanı

ESP32Encoder kütüphanesinin varsayılanı pull-DOWN'dır; açık-kolektör encoderlar bununla hiç veri üretmez. useInternalWeakPullResistors = puType::up; şart.

Firmware

PWM tight-loop hatası

spin()'in bir döngü içinde tekrar tekrar çağrılması LEDC donanımını bozar. Bkz. §08.

Kablolama

RST / 3.3V pin karışıklığı

Bu iki pin çoğu ESP32 kartında yan yanadır. Encoder Vcc'nin RST'ye bağlanması, kartın kendini sürekli resetlemesine ve gürültülü encoder verisine yol açar.

Kinematik

Motor1/Motor2 kimlik takası

Yalnızca düz gitmek doğru ama dönüşler ters çalışıyorsa, tek bir motorun _INV bayrağını değil, Motor1↔Motor2'nin tüm config bloğunu (pin, encoder, INV) birlikte takas edin.

Performans

RPi4 + RViz üzerinden WiFi

RViz'i WiFi üzerinden sürekli açık bırakmak, ROS2/DDS'in geri basınç (back-pressure) yaşamasına ve micro_ros_agent'ın senkron kaybetmesine yol açabilir. Sadece kontrol için aç, sonra kapat.

Mekanik

Şaft-adaptör toleransı

Bkz. §05 — zorlanarak takılan plastik adaptör tekerlek sallanmasının en sık nedenidir.

Güç

Sürücü güçsüzken test etmeyin

Sadece ESP32+RPi4 test edilirken BTS7960 güçsüz bırakılırsa, PWM hattı seri iletişime gürültü bindirip NotEnoughMemoryException ile agent'ı çökertebilir.

WiFi

brcmfmac sürücüsü motor yükünde düşüyor

Motor aktivitesinden hemen sonra RPi4'ün WiFi'si tamamen kayboluyor ("No wifi adaptor found"). lsmod | grep brcm boş çıkar. Çözüm: sudo modprobe brcmfmac — reboot gerekmez.

SLAM/Nav2

LIDAR/SLAM durunca köprü (EKF) kopuyor

LIDAR ya da SLAM'i Ctrl+C ile durdurunca /odom (EKF çıktısı) ve TF'teki odom çerçevesi kayboluyor — USB kopması yok, EKF düğümü sessizce takılı kalıyor. /odom/unfiltered (ham ESP32 verisi) etkilenmiyor, bu yüzden fark edilmesi zor. Çözüm: sudo systemctl restart linorobot2_bringup.service. start_robot.sh'nin cleanup() fonksiyonu bunu otomatik yapar (bkz. §14).

RViz/QoS

LIDAR Best Effort, RViz varsayılanı Reliable

RViz'de /scan hiç görünmez, log'da incompatible QoS uyarısı çıkar. LIDAR sürücüsü Best Effort yayınlıyor, RViz display'in varsayılanı Reliable. Çözüm: RViz config dosyasında (.rviz) LaserScan display'in Reliability Policy'sini Best Effort yapın.

Geliştirme ortamı

VSCode snap sandbox, GUI uygulamalarını bozuyor

VSCode kendisi snap paketiyse, içindeki terminalden (ya da ona bağlı bir araçtan) rviz2 gibi GUI uygulamaları libpthread.so.0 ... undefined symbol hatasıyla çöker. Çözüm: GUI araçlarını VSCode'un dışındaki bağımsız bir terminalden açın.

Ağ

RPi4'ü IP değiştiğinde MAC'ten bulma

DHCP her açılışta farklı IP verebiliyor. Çözüm: bilinen WiFi MAC'inden (ip neigh show | grep <mac>, önce ağı taramak için ping ile ARP tablosunu doldurun) cihazı bulun — IP'yi tahmin etmekten çok daha güvenilir.

Ağ

GNOME "No Wi-Fi Adapter Found" ama wlan0 var

Netplan renderer: networkd olduğunda, GNOME'un WiFi paneli (NetworkManager'a bakar) cihazı görmez — ama ip link show wlan0'da arayüz gerçekten var. Çözüm: netplan dosyasında renderer: NetworkManager yapıp sudo netplan apply.

URDF

Encoder/tik kalibrasyonu, URDF ölçüleriyle karışmasın

esp32s3_config.h'deki WHEEL_DIAMETER/COUNTS_PER_REV odometri hesaplamasını, 2wd_properties.urdf.xacro'daki ölçüler ise sadece RViz görselleştirmesini etkiler — ikisi birbirinden bağımsız dosyalardır, biri güncellenince diğeri otomatik güncellenmez.

#!/bin/bash

LOG_DIR="$HOME/robot_logs"
mkdir -p "$LOG_DIR"

cleanup() {
  echo ""
  echo "Kapatiliyor (LIDAR + SLAM)..."
  kill $(jobs -p) 2>/dev/null
  wait 2>/dev/null
  echo "Temel sistem (micro-ROS koprusu) temiz durum icin yeniden baslatiliyor..."
  sudo systemctl restart linorobot2_bringup.service
  sleep 3
  echo "Tamam. Koprunu tekrar ayakta, joystick/cmd_vel calismali."
}
trap cleanup EXIT INT TERM

source /opt/ros/humble/setup.bash
source "$HOME/linorobot2_ws/install/setup.bash"

echo "[0/2] Temel sistemin (linorobot2_bringup.service) hazir olmasi bekleniyor..."
if ! systemctl is-active --quiet linorobot2_bringup.service; then
  echo "  Servis aktif degil, baslatiliyor..."
  sudo systemctl start linorobot2_bringup.service
fi

for i in $(seq 1 20); do
  if ros2 topic list 2>/dev/null | grep -q "^/odom/unfiltered$"; then
    echo "  Temel sistem hazir (/odom/unfiltered goruluyor)."
    break
  fi
  sleep 1
  if [ "$i" -eq 20 ]; then
    echo "  UYARI: 20 saniyede /odom/unfiltered gorulemedi, yine de devam ediliyor."
    echo "  Kontrol icin: systemctl status linorobot2_bringup.service"

class DpadTeleop(Node):
    def __init__(self):
        super().__init__('dpad_teleop')
        self.create_subscription(Joy, 'joy', self.joy_cb, 10)
        self.pub = self.create_publisher(Twist, 'cmd_vel', 10)

    def joy_cb(self, msg: Joy):

            if msg.buttons[DPAD_UP]:
                twist.linear.x = LINEAR_SPEED
            elif msg.buttons[DPAD_DOWN]:

        self.pub.publish(twist)

    node = DpadTeleop()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()

go_1m_test.py — ~/ (RPi4)

Odometri kalibrasyonu için otomatik 1m/2m düz sürüş test betiği.

#!/usr/bin/env python3
import math
import sys
import time

import rclpy
from geometry_msgs.msg import Twist
from nav_msgs.msg import Odometry
from rclpy.node import Node

TARGET_M = 1.0
CRUISE_MPS = 0.10
CREEP_MPS = 0.05
CREEP_ZONE_M = 0.15
TIMEOUT_S = 30.0


class OneMeterTest(Node):
    def __init__(self):
        super().__init__("one_meter_test")
        self.pub = self.create_publisher(Twist, "/cmd_vel", 10)
        self.create_subscription(Odometry, "/odom/unfiltered", self.odom_cb, 10)
        self.x0 = None
        self.x = self.y = None
        self.start_t = None
        self.done = False
        self.timer = self.create_timer(0.05, self.step)

    def odom_cb(self, msg):
        self.x = msg.pose.pose.position.x
        self.y = msg.pose.pose.position.y
        if self.x0 is None:
            self.x0, self.y0 = self.x, self.y

    def distance(self):
        return math.hypot(self.x - self.x0, self.y - self.y0)

    def send(self, v):
        t = Twist()
        t.linear.x = v
        self.pub.publish(t)

    def stop(self):
        for _ in range(20):
            self.send(0.0)
            time.sleep(0.02)

    def step(self):
        if self.done:
            return
        if self.x0 is None:
            if self.start_t is None:
                self.start_t = time.time()
            if time.time() - self.start_t > 5.0:
                print("HATA: 5 sn icinde /odom/unfiltered gelmedi, durduruluyor.")
                self.finish()
            return
        if self.start_t is None:
            self.start_t = time.time()
            print("Baslangic alindi, ileri gidiliyor...")
        d = self.distance()
        if d >= TARGET_M:
            self.finish(d)
            return
        if time.time() - self.start_t > TIMEOUT_S:
            print(f"ZAMAN ASIMI ({TIMEOUT_S}s), durduruluyor. Odometre mesafesi: {d:.3f} m")
            self.finish(d)
            return
        v = CREEP_MPS if (TARGET_M - d) < CREEP_ZONE_M else CRUISE_MPS
        self.send(v)

    def finish(self, d=None):
        self.done = True
        self.timer.cancel()
        self.stop()
        if d is None and self.x0 is not None:
            d = self.distance()
        if d is not None:
            print("")
            print(f"Odometre (Euclid) mesafe : {d:.3f} m")
            print(f"Hedef                    : {TARGET_M:.3f} m")
            print("Simdi mezuru ile gercek mesafeyi olc ve buraya yaz.")
        print(f"Son odom konumu  x={self.x} y={self.y}" if self.x is not None else "")


def main():
    rclpy.init()
    node = OneMeterTest()
    try:
        while rclpy.ok() and not node.done:
            rclpy.spin_once(node, timeout_sec=0.05)
    except KeyboardInterrupt:
        print("\nCtrl+C: durduruluyor.")
        node.stop()
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == "__main__":
    sys.exit(main())

#!/usr/bin/env python3
"""RPLIDAR icin dogru baud'u bulmak icin taranan hizlarda a5 5a sync baytini arar."""
import serial
import time

PORT = "/dev/ttyUSB0"
BAUDS = [9600, 19200, 57600, 115200, 128000, 230400, 256000, 460800, 921600, 1000000]

for baud in BAUDS:
    try:
        ser = serial.Serial(PORT, baud, timeout=1.5)
        ser.reset_input_buffer()
        time.sleep(0.3)
        data = ser.read(500)
        ser.close()

import math, rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState

class Track(Node):
    def __init__(self):
        super().__init__("joint_track")
        self.create_subscription(JointState, "/joint_states", self.cb, 10)
        self.start = None; self.last = None
    def cb(self, m):
        pos = dict(zip(m.name, m.position))
        if not all(k in pos for k in ("left_wheel_joint", "right_wheel_joint")): return
        self.last = pos
        if self.start is None: self.start = pos
    def report(self):
        if not self.start or not self.last:
            print("joint verisi yok"); return
        for k in ("left_wheel_joint", "right_wheel_joint"):
            print(f"{k}: {(self.last[k]-self.start[k])/(2*math.pi):.3f} tur")

rclpy.init(); n = Track()
try:
    rclpy.spin(n)
except KeyboardInterrupt:
    n.report()

odom_track.py — ~/ (RPi4)

/odom/unfiltered üzerinden kat edilen yolu ve başlangıca uzaklığı canlı izler — sapma/kalibrasyon testlerinde kullanılan araç (bkz. §08).

import math, time, rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry

class Track(Node):
    def __init__(self):
        super().__init__("odom_track")
        self.create_subscription(Odometry, "/odom/unfiltered", self.cb, 10)
        self.x0 = None; self.last = None; self.path = 0.0; self.t = time.time()
    def cb(self, m):
        x, y = m.pose.pose.position.x, m.pose.pose.position.y
        if self.x0 is None:
            self.x0, self.y0 = x, y; self.last = (x, y); return
        self.path += math.hypot(x - self.last[0], y - self.last[1]); self.last = (x, y)
        if time.time() - self.t > 0.5:
            self.t = time.time()
            print(f"baslangica uzaklik: {math.hypot(x-self.x0, y-self.y0):.3f} m   toplam yol: {self.path:.3f} m", flush=True)

rclpy.init(); n = Track()
try:
    rclpy.spin(n)
except KeyboardInterrupt:
    print(f"\nSON -> baslangica uzaklik: {math.hypot(n.last[0]-n.x0, n.last[1]-n.y0):.3f} m   toplam yol: {n.path:.3f} m")
